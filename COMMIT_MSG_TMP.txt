fix: 声明 dsh.bundle，使包能作为组合包安装

安装时报 "dsh-billing declares no dsh.bundle"。DSH 只把 dsh.profile.bundles
里的包当作组合层加载，而每个这样的包必须在 package.json 里声明
dsh.bundle.patch；缺了它，install_bundle 以 not-a-bundle 拒绝，启动时也
只被当成普通依赖。

- 新增 cordis.patch.yml：插入本包插件行（这正是 files[] 里列了很久、
  却从未创建的那个文件）
- package.json：新增 dsh.bundle.patch；exports 增加 ./cordis.patch.yml；
  files[] 加回 cordis.patch.yml
- dsh.client.platform 与 dsh.bundle 并存：前者让浏览器半进
  window.__DSH_BOOT__，后者让 Node 半成为组合层

重写安装方式（原来的做法是错的）：
- 旧 install.ps1 手工建 junction 并往 profile 的 cordis.patch.yml 插块，
  绕过了 dsh.profile.bundles，pnpm 下次 install 会丢掉链接、插件静默消失
- 改为调用官方的 dsh plugin --profile web add <目录>，由 profile 自己的
  pnpm 写入 link: 依赖并登记进 dsh.profile.bundles
- uninstall.ps1 对应改为 dsh plugin remove，并清理 pnpm 留下的符号链接

新增 tests/bundle.mjs：复现 DSH 的 bundlePatchFiles 类型校验，并检查
exports / files[] / main / client 面完整性，防止清单再次漂移。

已验证：真实安装进 web profile 后 dsh-billing 出现在 dsh.profile.bundles
且为 SymbolicLink；卸载后 profile 的 package.json 与 cordis.patch.yml
逐字节恢复原状；install/uninstall 幂等。
